고민 입력창, 칩, 점수를 코드에서 어떻게 부르고 상태가 어떻게 유지되는지 적는다.

## 어디에 있나

화면 정본 안의 요소와 클래스다. 세 가지 모두 화면을 그린 뒤 wire 가 동작을 붙인다.

## 만드는 법

입력창은 textarea 요소를 그대로 쓴다. 클래스를 붙이지 않는다. 고민 입력(04)에서는 입력창 바로 아래에 신 컨텍스트 자리를 둔다. 도우미 함수 deityContext 가 빈 상자를 만들고, 사용자가 글을 적기 시작하면 내용이 채워진다.

칩은 chips 로 감싸고 안에 chip 클래스의 button 을 둔다. 여러 개를 고를 수 있다.

점수는 score 로 감싸고 안에 button 다섯 개를 둔다. 하나만 고를 수 있다.

## 넘기는 값

세 가지 모두 속성으로 값을 받지 않는다. 글자가 곧 값이다. 고른 결과는 화면 상태에 기록된다.

* 칩은 화면 id, 묶음 순서, 글자를 합친 이름으로 기억한다. 그래서 신을 바꿔 화면을 다시 그려도 고른 칩이 남는다.
* 점수는 같은 묶음 안에서 하나만 선택으로 표시된다.
* 입력창의 글은 화면 상태의 worry 에 들어간다. 고민부터 다시 시작하는 버튼을 누르면 지워진다.

## 상태

* 입력창은 평소 1px 얇은 테두리이고, 포커스를 받으면 2px 차콜로 굵어진다. 안내 문구는 흐린 색이다.
* 칩은 고르면 차콜로 채우고 글자를 굵게 한다.
* 점수는 고르면 옅은 틴트와 차콜 테두리가 된다.
* 선택 표시에 유채색을 쓰지 않는다.

## 이렇게 하지 않는다

* 칩과 점수에 직접 클릭 이벤트를 붙이지 않는다. wire 가 연결한다. 직접 붙이면 화면을 다시 그릴 때 두 번 실행된다.
* 입력창 안내 문구를 디자인 문서에서 새로 쓰지 않는다. 문구는 Copy Master가 정한다.
* 고민 입력(04)의 개인정보 안내를 입력창 아래에서 옮기거나 첫 화면 밖으로 밀지 않는다. 잠긴 문구 자리다.

## Figma와 다른 점

Figma의 입력창은 기본, 포커스, 입력됨 세 변형이다. 코드에는 입력됨이라는 상태가 따로 없고, 글이 있으면 자동으로 그렇게 보인다. 안내 문구 색은 Figma와 코드 모두 선 토큰 값을 쓰고 있는데, 글자 전용 토큰을 만들지는 아직 정하지 않았다.

## 접근성

오늘 가능한 정도(05)의 선택 카드는 button 이 아니라 div 다. 키보드로 고를 수 없다. 확인사항의 접근성 절에 있다.

grep -n "class=\"chips\"\|class=\"score\"\|textarea" prototype/todaktodak-working.html
