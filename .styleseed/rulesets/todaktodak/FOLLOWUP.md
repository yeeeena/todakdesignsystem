## P1 — 과거 내용이 현재 기준으로 오인될 수 있음

### 1. `COMPONENTS.md` — 신별 콘텐츠를 "정본"으로 지목

상담 결과 화면 설명 끝에 신별 콘텐츠의 정본이 `docs/신별_동적화_설계.md`라고 적혀 있습니다.
PM 기준에 따르면 신별 콘텐츠·상담 내용·매칭은 **현재 구현 기준 문서**가 정본이고,
패키지의 그 문서는 과거 배경 자료입니다.

**수정 방향** — "정본" 표현을 걷어내고 현재 구현 기준 문서를 가리키도록. 패키지 파일은 히스토리로 표시.

### 2. `README.md` — 참고자료를 "6신 콘텐츠 정본"으로 소개

파일 구성 표에서 `참고자료/신별_동적화_설계.md`를 "6신 콘텐츠 정본"으로 설명합니다.
1번과 같은 문제이고, README는 처음 여는 문서라 오인 가능성이 더 큽니다.

**수정 방향** — "과거 콘텐츠 설계 배경(현재 기준 아님)"으로 문구 교체.

### 3. `checks.md` — 필수 고지 문구를 직접 인용

문구 점검 절이 실제 문구를 따옴표로 인용하고 있습니다.
문구 정본은 **문구 관리 / Copy Master**이므로, 디자인 문서가 과거 문구를 정본처럼 다시 정의하는 모양이 됩니다.

**수정 방향** — 인용문을 빼고 **"이 화면에 이 고지가 있는가"** 형태의 점검 항목만 남기기.
문구 확인은 문구 관리 문서로 넘기는 링크를 답니다.

### 4. ~~패키지 내부 프로토타입 — 스냅샷 표시 없음~~ ✅ 처리됨

파일명만으로는 현재 최종 프로토타입인지 과거 스냅샷인지 구분되지 않던 문제.
**조치** — `토닥토닥_프로토타입_스냅샷_2026-08.html`로 이름에 시점을 박고, `DESIGN.md` §0·README에 히스토리 자료로 표시.
남은 것: 화면 상단 배지에도 스냅샷 문구를 넣을지는 선택 사항.

## P2 — 최신 자료와 대조 필요

### 5. `RULESET.md` · `COMPONENTS.md` — 화면 구조·CTA 서술

두 문서가 화면 번호(01–13)와 CTA 구성을 전제로 서술돼 있습니다.
최종 프로토타입에서 화면이 추가·삭제·재배치됐다면 어긋납니다.

**대조 항목** — 화면 번호 체계 / 부적 화면 하단 버튼 구성 / 고민 입력의 신 추천·변경 흐름 /
신 선택 시트의 존재 여부.

### 6. `COMPONENTS.md` — 화면 맵 표

16개 화면의 id·이름·전용 컴포넌트를 나열합니다. 최종 프로토타입 화면 목록과 1:1 대조가 필요합니다.

### 7. `evidence.json` — 미해결 항목의 현재 유효성

9건 중 일부는 이미 결정됐거나 최신 기준에서 무의미해졌을 수 있습니다.
특히 로더 적용 여부, 버튼 라벨 통일은 그 사이 정해졌을 가능성이 있습니다.

**대조 방향** — 기준 문서와 맞춰 해결된 항목을 정리하고, `DESIGN.md` §7과 동기화.

### 8. `reference-board.html` — 컴포넌트 라이브 렌더

보드에 렌더된 버튼·카드·시트가 최종 프로토타입과 다르면 눈으로 보는 기준이 어긋납니다.
5번 대조 후 달라진 부분만 갱신하면 됩니다.

## P3 — 정리하면 좋음

### 9. `INDEX.md` · `README.md` — `DESIGN.md`와 역할 중복

셋 다 "먼저 읽는 문서" 성격이 있어 진입점이 셋으로 보입니다.

**정리 방향** — `DESIGN.md`를 유일한 진입점으로 두고,
`README.md`는 패키지 열기 안내, `INDEX.md`는 옵시디언 링크 허브로 좁히기.
(이번에 두 파일 상단에 "DESIGN.md부터" 안내를 넣어 1차 정리해 두었습니다.)

### 10. `adapter.json` — 빌드 레시피의 현재 유효성

공유용 HTML 빌드 규칙이 담겨 있는데, 최종 프로토타입이 별도로 관리된다면
이 레시피가 계속 필요한지 확인이 필요합니다.

### 11. 라이팅 가이드 부재 안내

`WRITING.md`는 문구 정본이 별도 문서라 제거했습니다.
`INDEX.md`에 링크 자리를 만들어 뒀으니, 문구 관리 문서가 확정되면 연결하면 됩니다.
