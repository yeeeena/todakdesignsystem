# 토닥토닥 디자인 가이드 — 허브 (MOC)

> 이 폴더가 디자인 정본입니다. 어떤 파일을 언제 보는지, 옵시디언에서 어떻게 연결하는지 정리.

## 파일 구성과 용도

| 파일 | 무엇 | 언제 보나 |
|---|---|---|
| [[RULESET]] | 12축 디자인 계약 (판단 기준) | **새 화면을 설계할 때** — "이 앱답게"의 정의 |
| [[COMPONENTS]] | 컴포넌트·자산 인벤토리 (구현 사전) | **화면을 만들거나 고칠 때** — 있는 부품 먼저 찾기 |
| [[checks]] | 필수/금지 tell + 회귀 시나리오 | **작업 끝나고 셀프 리뷰할 때**, PR 전 |
| `tokens.json` | 기계가독 토큰 값 | 정확한 수치가 필요할 때 (색·라운딩·타이밍) |
| `evidence.json` | 출처·신뢰도·**미해결 항목** | 팀 결정이 필요한 것 확인할 때 |
| `adapter.json` | 캔버스 계약·번들 레시피 | 공유용 단일 HTML 빌드할 때 |
| `reference-board.html` | 이미지 내장 시각 보드 | 눈으로 확인할 때 (브라우저로 열기) |

## 추천 워크플로우

- **새 화면 만들기**: [[RULESET]] §해당 축 → [[COMPONENTS]]에서 부품 조합 → 완성 후 [[checks]] 통과
- **디자인 리뷰**: [[checks]]만 놓고 화면과 대조 (tell 있음? anti-tell 없음?)
- **값 질문** ("라운딩 몇이었지?"): `tokens.json` 검색
- **"이거 왜 이렇게 됐지?"**: `evidence.json`의 출처·미해결 확인
- **팀 공유**: `reference-board.html` 전달 또는 프로토타입 단일 HTML 재빌드(`adapter.json` 레시피)

## 연결 구조 (링크 그래프)

```
STYLESEED.md (프로젝트 락, 루트)
 └─ INDEX (여기) ─┬─ RULESET ──┬─ COMPONENTS (상세 스펙 위임)
                  │            ├─ checks (검증 위임)
                  │            └─ reference-board.html (시각 증거)
                  ├─ COMPONENTS ── prototype/todaktodak-working.html (소스)
                  ├─ checks
                  └─ evidence.json ── docs/신별_동적화_설계.md (콘텐츠 정본)
```

옵시디언 그래프에서 허브가 되도록 이 문서에서 전부 링크: [[RULESET]] · [[COMPONENTS]] · [[checks]]
관련 외부 노트: 콘텐츠 정본은 `docs/신별_동적화_설계.md`, 프로젝트 락은 루트 `STYLESEED.md`.

## 옵시디언 연동 시 주의 (중요)

1. **닷폴더 문제**: 옵시디언은 `.styleseed/` 같은 숨김 폴더를 인덱싱하지 않습니다.
   이 저장소에는 보이는 경로로 심링크가 걸려 있어요 → **`docs/design-guide/`** 로 접근하면
   볼트에 정상 표시되고, 원본과 자동 동기화됩니다(복사본 아님).
2. **링크 방식**: 문서 간 링크는 표준 마크다운 상대경로라 옵시디언에서 그대로 동작합니다.
   위키링크([[...]])로 걸려면 볼트 설정 → "Files & Links → New link format: relative" 권장.
3. **HTML/JSON**: `reference-board.html`은 옵시디언이 렌더하지 못하니 "기본 앱으로 열기"로.
   json은 코드블록 뷰로만 보입니다 — 수치 검색용으로 쓰세요.
4. **편집 규칙**: 이 폴더 문서를 고치면 곧 디자인 정본이 바뀌는 것입니다.
   구현과 어긋나게 수정하지 말고, 바뀐 구현 → 문서 갱신 순서로. (자동 검증: COMPONENTS는
   CSS 클래스 152종 전수 커버 기준 — 클래스를 추가했다면 문서에도 추가)
