## 1. 디자인 방향과 핵심 원칙

토착신이 사용자의 고민을 읽고 부적으로 남겨주는 **감정 케어 서비스**입니다.
점술이 아니라 **오늘의 고민을 정리하는 도구**라는 위치가 디자인 전반을 지배합니다.

### 다섯 가지 원칙

**1) 선형 흐름 — 한 화면 = 한 결정**
대시보드·탐색형이 아닙니다. 화면마다 주 행동 1개 + 보조 행동 2개 이하.
진입은 두 갈래(**고민부터** / **신부터**)지만 고민 입력 단계에서 한 흐름으로 합류합니다.

**2) 일러스트가 절반**
몰입 화면은 풀블리드 일러스트가 첫 시선이고, 텍스트·버튼은 그 위에 코드 레이어로 얹힙니다.
캐릭터가 카드 위로 살짝 겹치는 배치, 실루엣대로 반응하는 탭 — 이런 것이 이 서비스의 인상을 만듭니다.

**3) 위계는 색이 아니라 불투명도와 굵기로**
warm mono가 기본입니다. 크림 바탕 + 차콜 잉크. 유채색으로 위계를 만들지 않습니다.
색은 **신별 몰입 순간**에만 크게 씁니다.

**4) 재촉하지 않는 톤**
"~해도 괜찮아요", "안 해도 돼요"가 반복되는 조력자의 목소리입니다.
느낌표·이모지를 쓰지 않고, 감정은 어휘로 전달합니다.
※ 실제 문구는 **문구 관리 문서가 정본**입니다. 이 원칙은 디자인이 그 톤을 방해하지 않기 위한 것입니다.

**5) 정리 도구임을 반복해서 밝힌다**
면책·개인정보·공유 범위 고지가 특정 화면에 붙어 있습니다.
**디자인을 고칠 때 이 고지 자리가 사라지지 않아야 합니다**(§6, `checks.md` §문구).

## 2. 토큰 사용 원칙

정확한 값은 `tokens.json`, 설명이 붙은 표는 `COMPONENTS.md` §1에 있습니다. 여기서는 **쓰는 규칙**만.

### 2-1. 컬러

| 층 | 값 | 용도 |
|---|---|---|
| 배경 | `--cream #f7f4ed` | 페이지 바탕 |
| 표면 | `--surface #FFFDFC` | 카드·버튼 표면 |
| 잉크 | `--charcoal #1c1c1c` | 본문·제목·주 버튼 |
| 잉크 사다리 | `ink-83 / 82 / 40 / 08 / 04 / 03` | 보조 텍스트 → 테두리 → 헤어라인 → 틴트 |

- **순검정 `#000` 금지.** 잉크는 항상 차콜입니다.
- **위계는 잉크 불투명도와 굵기로.** 색을 바꿔 강조하지 않습니다.
- **`<button>`에는 `color`를 반드시 지정합니다.** 브라우저 기본값이 순검정이라 그대로 두면 원칙이 깨집니다.
- 새 코드는 **SEED 역할 토큰(`--seed-color-*`)** 을 씁니다. 레거시 별칭(`--blue-500` 등)은 참조용입니다.

**신별 색은 두 층입니다 — 섞어 쓰지 마세요.**

| 층 | 어디에 | 규칙 |
|---|---|---|
| **딥컬러** (`bg`) | 상담 결과 배경, 저장/공유 딤 | **배경 전용.** 버튼·테두리 등 컨트롤 색으로 쓰지 않음 |
| **라벨톤** (`label`) | 결과·부적 화면의 미니타이틀, 신 컨텍스트의 이름 | 표면 위 대비 4.5:1을 통과하도록 어둡게 조정한 값. **목록·비교 UI에서는 쓰지 않음**(신들이 동등하게 읽혀야 함) |

> ⚠️ 이 두 층의 경계는 아직 완전히 정리되지 않았습니다 → §7 확인 필요 1번.

**시맨틱 색**은 안전 안내·생성 실패 화면 전용입니다. 상태를 무지개로 표현하지 않습니다.

### 2-2. 타이포그래피

**Pretendard 단일 패밀리.** 페이지 제목 24 → 인용 20 → 카드 제목 17 → 본문 15 → 보조 14 → 미니라벨 13 → 캡션 12.

- **자간은 항상 0 이하.** 양수 자간·uppercase 오버라인을 쓰지 않습니다.
- **Regular(400) 이하를 쓰지 않습니다.** 최소 Medium(500).
- 한글 줄바꿈이 어색해지는 자리(다크 배경 제목, 좁은 폭의 이름)는 `word-break: keep-all`.
- 이름 뒤 조사(이/가)는 받침에 따라 자동 선택합니다 — 하드코딩하지 않습니다.

### 2-3. 간격 · 라운딩 · 레이아웃

- **캔버스 390×844**, 본문 좌우 여백 24px(콘텐츠 폭 342px), **8px 그리드**.
- 카드 패딩 18–20 · 카드 간 12 · 섹션 간 24–26. 허용 오차 ±4px.
- 라운딩 사다리: `8 / 12 / 14 / 16 / 20 / 24 / 32 / 999`. **카드는 16**, 시트 상단은 20–24.
- 그림자는 뉴트럴 저강도만. 하드섀도는 **시작 화면 버튼 하나의 예외**이고 다른 곳으로 번지지 않습니다.

### 2-4. 모션

- duration `120 / 200 / 320ms`, ease 2종. **UI 전환은 320ms 이하**(부적 뒤집기 640ms만 예외).
- 눌림은 오버레이로: 어두운 버튼엔 밝은 오버레이, 밝은 버튼엔 어두운 오버레이.
- **모든 모션은 `prefers-reduced-motion`에서 꺼집니다.** 새 모션을 넣으면 이 대응을 같이 넣습니다.
- 무한 회전 스피너·스켈레톤 시머를 쓰지 않습니다(§3-6).

## 3. 핵심 컴포넌트 사용 기준

전체 목록과 정확한 수치는 `COMPONENTS.md`, 눈으로 볼 때는 `reference-board.html`.

### 3-1. 버튼

| 위계 | 형태 | 언제 |
|---|---|---|
| 주 | 차콜 채움 · 52px · r12 | 화면당 1개 |
| 보조 | 표면 + 테두리 · 52px | 되돌아가기, 대안 행동 |
| 3차 | 고스트 / 밑줄 텍스트 | 부가 행동 |

- 화면 하단에 **버튼이 3개** 필요하면: 주 행동 1개를 전폭으로 위에, 보조 2개를 한 줄로 아래.
  같은 위계 3개를 한 줄에 늘어놓지 않습니다.
- 페어 버튼은 16px 라벨, 단독 CTA는 18px.
- 버튼 라벨은 **행동을 말하는 형태**로. 실제 문구는 문구 관리 문서를 따릅니다.

### 3-2. 카드

기본(표면 + 얇은 테두리) / 소프트(연한 배경, 테두리 없음) / 틴트 3단.
**딥컬러 배경 위에서는 2px 차콜 테두리**로 톤을 눌러줍니다.
카드 패딩이 14px 미만으로 촘촘해지지 않게 합니다.

### 3-3. 입력 · 칩

- 텍스트영역은 포커스 시 테두리가 2px 차콜로 굵어집니다.
- 칩은 36px 필. 선택되면 **차콜 채움 + 굵기 상승** — 색이 아니라 채움으로 표시합니다.
- 점수 선택(1–5)은 연한 틴트 + 차콜 테두리.

### 3-4. 바텀시트

세 종류가 같은 문법을 공유합니다.

| 시트 | 성격 |
|---|---|
| 신 소개 시트 | 화면 위로 올라오는 전역 시트. 상단 라운딩 24, 최대 높이 76% |
| 스텝 시트 (고민 정리) | 화면 하단 고정 패널. **상단 위치가 높이가 아니라 폭에 비례** — 일러스트와의 겹침을 기기 폭에 관계없이 유지 |
| 신 선택 시트 | 전역 시트를 재사용하고 내용만 목록으로 교체 |

**목록형 시트에서 항목은 카드 문법 그대로**(표면 + 얇은 테두리 + r16) 씁니다.
선택 표시는 칩·점수와 같은 관용구(**차콜 테두리 + 연한 틴트**)이고, 신별 색을 쓰지 않습니다.

### 3-5. 아이콘

뒤로·닫기·셰브런은 **전부 24px SVG, stroke 1.8**.
문자 글리프(`✕` `›`)나 이모지를 아이콘으로 쓰지 않습니다 — 굵기와 정렬이 폰트에 끌려갑니다.

### 3-6. 로더 · 진행 표시

- **로딩 = 캐릭터 링 로더.** 원형 링이 채워지는 동안 신 아바타가 순환합니다.
- **진행 = 상단 HUD 바.** 일러스트 위에 흰 라벨 + 가는 진행바.
- 3-dot 로더는 레거시(미사용), 스켈레톤 시머는 금지입니다.

## 4. 화면에서 반드시 유지해야 하는 특징

> ⚠️ 아래는 **디자인 가이드 패키지 스냅샷 기준**입니다.
> 화면 구성·CTA·인터랙션의 현재 정본은 **최종 프로토타입**이므로, 실제 작업 전 대조해 주세요(§7).
> 여기 적은 것은 "이 특징이 사라지면 서비스가 서비스답지 않게 된다"는 **디자인 자산**입니다.

| 화면 | 유지해야 하는 것 |
|---|---|
| 신 목록 | 캐릭터를 누르면 **실루엣 모양 그대로** 살짝 커졌다가 소개 시트가 뜸. 뒤 캐릭터가 비치지 않아야 함 |
| 고민 정리 (3단계) | 상단 일러스트 + 하단 라운드 시트의 분할. 시트 상단은 **폭 비례** |
| 상담 결과 | 신별 딥컬러 몰입 배경 + **캐릭터가 카드 위로 살짝 겹치는 배치** |
| 나만의 부적 | 부적 카드를 탭하면 앞뒤가 뒤집힘. 진입 시 1회 힌트 |
| 저장/공유 | 부적 아트를 크게 흐린 배경 + 신별 딤. 카드 모서리는 라운딩으로 잘라냄 |
| 로딩 (2종) | 캐릭터 링 로더 |
| 안내 3종 | 제목만 시맨틱 색, 본문은 기본 잉크 |

**진입 경로에 따라 갈리는 것** — 신을 골라 들어왔는지가 화면에 남아 세 가지를 바꿉니다.

1. 고민 정리 3단계의 **상단 일러스트** (신을 골라 들어왔을 때만 신별 아트, 아니면 공통)
2. **뒤로 가기 목적지** (신 목록 / 시작 화면)
3. 고민 입력의 **신 컨텍스트 표시 시점** (이미 골랐으면 바로, 아니면 고민을 적은 뒤 추천)

> 고민 입력 화면에서 신을 바꿔도 상단 일러스트는 공통을 유지합니다.
> 배경이 통째로 갈리면 화면이 바뀐 것처럼 읽히기 때문입니다.

**필수 고지가 붙는 자리** — 문구 자체는 문구 관리 문서가 정본이고, 여기서는 **자리**만 고정합니다.

| 화면 | 무엇을 밝히는가 |
|---|---|
| 시작 | 점술이 아니라 정리 도구라는 면책 |
| 고민 입력 | 개인정보를 적지 않아도 된다는 안내 |
| 나만의 부적 | 부적이 결과를 약속하지 않는다는 면책 |
| 저장/공유 | 공유물에 고민 원문이 포함되지 않는다는 안내 |
| 안전 안내 | 판단·진단하지 않고 전문 기관으로 연결 |

## 5. 접근성 · 반응형 · 텍스트 길이

### 접근성

- **대비 4.5:1 이상.** 특히 딥컬러 배경 위 텍스트는 표면색을 쓰고, 반투명 흰색을 본문에 쓰지 않습니다.
- 신별 라벨톤 6색은 표면 위 4.5:1을 통과하도록 조정된 값입니다 — 임의로 밝게 바꾸지 마세요.
- 아이콘 버튼에는 레이블을 답니다.
- 탭 가능한 요소는 실제 버튼 요소로 만듭니다(카드 전체가 눌리는 경우 포함).
- 모션은 `prefers-reduced-motion` 대응이 필수입니다.
- ⚠️ **키보드 포커스 링이 아직 정의돼 있지 않습니다** → §7 확인 필요 4번.

### 반응형

- **390px 단일 목표.** 520px 이하에서 프레임만 축소되고, 태블릿·데스크톱은 정의돼 있지 않습니다.
- 배경 좌표는 비율 기반이라 폭이 바뀌어도 따라옵니다.
- 스텝 시트 상단이 **폭에 비례**하는 이유가 이것입니다 — 높이 기준으로 바꾸면 겹침이 어긋납니다.

### 텍스트 길이 대응

- 신 이름 길이가 다릅니다(2–4자). **이름이 들어가는 자리는 가장 긴 이름 기준으로 확인**하세요.
- 조사는 받침에 따라 자동 선택됩니다.
- 좁은 폭의 텍스트는 `keep-all`로 어절 중간에서 끊기지 않게 합니다.
- ⚠️ 본문이 예상보다 길어질 때의 처리(말줄임 / 접기)가 정의돼 있지 않습니다 → §7 확인 필요 5번.

## 7. 확인 필요 항목

디자인 문서에서 임의로 결정하지 않고 남겨둔 것들입니다.

### 최신 기준과 대조가 필요한 것

**A. 화면 구성 · CTA · 인터랙션 전반** — §4는 패키지 스냅샷 기준입니다.
최종 프로토타입과 대조해, 화면 번호·CTA·인터랙션이 달라진 곳을 확인해야 합니다.
특히 **부적 화면 하단 버튼 구성**과 **고민 입력의 신 추천/변경 흐름**은 최근 바뀐 영역이라 우선 확인 대상입니다.

**B. 고정 UI 문구** — 이 문서는 문구를 정의하지 않지만, 패키지의 `checks.md`가
필수 고지 문구를 인용하고 있습니다. 문구 관리 문서와 대조가 필요합니다(후속 목록 참조).

**C. 신별 콘텐츠 · 매칭 로직** — 패키지 `참고자료/신별_동적화_설계.md`가
과거에 "정본"으로 표시돼 있었습니다. 현재 구현 기준 문서로 대체돼야 합니다(후속 목록 참조).

### 디자인 내부에서 아직 안 정해진 것

1. **신별 라벨톤의 지위** — 룰셋은 신별 색을 "배경 전용, 컨트롤 색 금지"로 정했는데,
   실제로는 결과·부적 화면의 미니타이틀에 라벨톤을 씁니다. 한 신은 두 값이 같아 규칙 위반처럼 보입니다.
   → **라벨톤을 별도 층으로 인정할지, 텍스트 강조를 차콜로 통일할지** 결정 필요.
2. **체크 표시 아이콘** — 완료 표시만 문자 글리프(`✓`)입니다. SVG로 통일할지.
3. **로더 디자인** — 피그마에 신별 파스텔 배경의 새 로딩 컷이 있으나 구현에 미반영. 적용 여부 결정 필요.
4. **키보드 포커스 링** — 정의돼 있지 않습니다. 접근성 기준으로 추가할지.
5. **긴 텍스트 처리** — 말줄임/접기 규칙이 없습니다. 신별 문구 길이가 크게 다를 때의 기준 필요.
6. **브랜드 락 불일치** — 과거 브랜드 문서의 주색(테라코타)과 현재 구현(차콜)이 다릅니다. 락 문서 갱신 여부.
