# 부적 시스템 분리

부적에 들어가는 그래픽은 화면 디자인 시스템과 따로 둔다. 2026-09-25에 PM이 정했다.

이 문서는 왜 나누는지, 어떻게 나눌지, 나눌 때 무엇을 해야 하는지를 적는다. 아직 옮기지 않았다.

---

## 왜 나누는가

둘은 읽는 사람도 정하는 것도 다르다.

| | 화면 디자인 시스템 | 부적 디자인 시스템 |
|---|---|---|
| 있는 곳 | docs/design-guide/ | 아직 없음 |
| 누가 읽나 | 사람과 AI가 화면을 만들 때 | 프로그램이 이미지를 합성할 때 |
| 정하는 것 | 토큰, 부품, 언제 무엇을 쓰는지 | 캔버스 규격, 슬롯 좌표, 폰트, 상태 단계 |
| 산출물 | 화면 | PNG 한 장 |
| 언제 바뀌나 | 화면이 늘거나 규칙이 정해질 때 | 그림을 다시 그리거나 슬롯을 옮길 때 |
| 검증 방법 | 화면 상태별 계산된 스타일 비교 | 조립 시안 눈 검수, 오버플로 계산 |

부적 스펙에는 토큰도 부품 계약도 필요 없고, 화면 가이드에는 bottom_y 583 같은 픽셀 좌표가 들어갈 자리가 없다. 한 폴더에 두면 AI가 화면을 만들 때 부적 좌표를 읽고, 부적을 만들 때 화면 토큰을 읽는다. 둘 다 방해가 된다.

## 접점은 하나

서로 알아야 할 것은 한 줄씩이다.

* 화면 쪽이 아는 것: 완성된 부적 카드가 620 곱하기 977 비율로 온다. 화면에서는 316 곱하기 498로 놓는다.
* 부적 쪽이 아는 것: 화면에 놓일 크기는 화면 시스템이 정한다. 부적 시스템은 카드 한 장을 만드는 데까지만 책임진다.

이 두 줄 말고는 서로의 문서를 읽지 않는다.

## 받은 것 (v7, 2026-09-25)

두 묶음으로 왔다. 지금은 내려받은 자리에 그대로 두었고 저장소에 넣지 않았다.

부적_런타임에셋_v7.zip — 20MB, 65개 파일

* 신별 10개 곱하기 6신 = 60장. base_front, base_back, character_state_1~3, symbol_state_1~3, background, pattern
* 폰트 2종. NanumSquareRound ExtraBold, Pretendard Medium. 둘 다 SIL OFL 1.1
* slots.json — 슬롯 5개의 좌표와 글자 규격. 신별 실측값 포함
* SPEC.md — 조립 순서, 슬롯 규격, 런타임 색상, 제작 메모

부적_조립시안_v7.zip — 6MB, 13개 파일

* 6신 곱하기 앞뒤 = 12장의 조립 검수 시안. 620 곱하기 977, 상태 2단계 기준
* 검수용 한 장

## 지금 정본과 무엇이 다른가

지금 프로토타입은 문구가 그림에 구워진 카드 한 장을 쓴다. v7은 빈 템플릿에 캐릭터와 상징과 문구를 런타임에 얹는다.

이 차이 때문에 2026-09-25에 찾은 문제가 v7에서는 생기지 않는다. 지금 부적 앞면 그림 여섯 장은 모두 서낭신 문구를 담고 있는데, v7 조립 시안은 신마다 다른 문구가 들어가 있다.

그 밖에 달라지는 것

* 캔버스가 1264 곱하기 1992에서 620 곱하기 977로 바뀐다. 화면에 놓을 때 비율은 같다.
* 상태가 1단계에서 3단계로 늘어난다. 어떤 상태를 언제 쓰는지는 기능명세가 정한다.
* 뒷면이 그림 한 장에서 상징과 키워드와 실천 문구 세 슬롯으로 나뉜다.

## 옮길 때 할 일

아직 하지 않았다. 옮기기로 하면 이 순서로 한다.

1. 둘 자리를 정한다. 같은 저장소의 docs/talisman/ 이거나 별도 저장소다. 같은 저장소면 에셋 20MB가 늘어 저장소가 50MB에서 70MB가 된다. 그림 작업자와 화면 작업자의 권한을 나눠야 하면 별도 저장소가 맞다.
2. 받은 두 묶음을 그 자리에 푼다. SPEC.md와 slots.json은 그대로 쓴다. 우리 문서 형식으로 다시 쓰지 않는다. 기계가 읽는 규격이라 형식을 바꾸면 깨진다.
3. CLAUDE.md의 읽는 순서에 한 줄을 더한다. 부적 그래픽 작업이면 부적 시스템의 SPEC.md만 읽고 화면 가이드는 읽지 않는다.
4. 화면 가이드의 부적 카드 문서에 접점 두 줄을 적는다. 그 문서가 부적 그림의 내용을 설명하지 않게 한다.
5. 정본을 v7으로 바꿀지 따로 정한다. 조립 시안 12장을 그대로 쓰면 문구 문제가 바로 없어지고 상태는 2단계로 고정된다. 런타임 조립까지 구현하면 상태 3단계와 문구 교체가 살아나지만 작업이 크다.
6. Figma 쪽은 부적 카드 부품의 신별 축을 어떻게 할지 함께 정한다. 지금은 앞면과 뒷면과 공유용 세 종류뿐이고 그림이 변형에 박혀 있다.

## 지금 상태

받은 파일은 내려받은 자리에 있다. 저장소에도 Figma에도 넣지 않았다. 정본도 건드리지 않았다.

부적 앞면 그림 여섯 장이 같은 문구를 담고 있는 문제는 docs/design-guide/확인사항.md 의 콘텐츠 절에 남아 있다. v7을 적용하면 사라진다.
